Choose an attack by the boundary you want to test: who supplies instructions, what the agent can read, which actions it can take, and what must remain protected. Each page explains the attack, a synthetic example, useful evidence and ways to reduce the risk.

The reference covers all **12 major families** in Martian's published catalogue, with focused pages for common injection and workflow attacks. The catalogue and the selectable technique list are different views: a family can be documented without a dedicated runnable technique.

| [Jailbreaks](/attacks/jailbreaks/) | A model is pushed past its safety policy |
| [Tool and action abuse](/attacks/tool-action-abuse/) | Tools perform an unauthorized or unsafe operation |
| [Memory and context poisoning](/attacks/memory-context-poisoning/) | Stored material changes later behavior |

## Use security frameworks

These frameworks answer different questions. Their mappings help organize an assessment; selecting a framework does not run every associated attack or certify a system.

- [MITRE ATLAS](/frameworks/mitre-atlas/) — adversary behavior against AI systems, including prompt injection, tools, memory and the AI supply chain.
- [MITRE ATT&CK](/frameworks/mitre-attack/) — adversary behavior across enterprise, mobile and industrial environments; useful when AI abuse reaches conventional infrastructure.
- [OWASP LLM Top 10](/frameworks/owasp-llm/) — application risk categories, including disclosure, output handling and excessive agency.
- [OWASP Agentic Top 10](/frameworks/owasp-agentic/) — risks in planning, delegated identity, tools, memory and agent coordination.
- [NIST AI RMF](/frameworks/nist-ai-rmf/) — a way to govern, understand, measure and manage risk across the lifecycle.

## Take a reference into an assessment

1. State the protected rule and the observable failure. For example: a support agent must not credit more than the authorized amount for one order.
2. Read the relevant attack page and confirm the required surface exists. A chat-only endpoint does not automatically provide document planting, memory editing or MCP descriptor control.
3. [Find available techniques in Attack Library](/library/coverage/), then [configure the assessment](/assessments/configure/). Use an approved target, synthetic records and a bounded budget.
4. Inspect [actual attempts and evidence](/assessments/evidence-and-results/). Separate a proposed action, a dispatched action and a verified effect. A timeout or unknown action remains unresolved.
5. Retain the evidence and [add a regression case](/evals/regression-cases/) where the relevant behavior can be reproduced safely.

All examples in this reference are explanatory synthetic examples. They are not newly executed walkthroughs or ready-made Martian configuration files. Target support and execution limits are described in [supported targets](/reference/supported-targets/) and [reproduction and limits](/assessments/reproduction-and-limits/).

The observed selectable list contains **36 techniques: 32 marked In the library and four Declared gaps**. The gaps are **MT-20 Session hijack**, **MT-24 Standing backdoor**, **MT-32 Price arbitrage** and **MT-36 Worker collusion**. Availability can differ by environment; confirm the live list before selecting scope.
