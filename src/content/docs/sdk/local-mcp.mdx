<Aside type="note" title="SDK version">
Activate your [SDK environment](/sdk/local-installation/) and install SDK 0.4.0 or later with both extras. With pip, run the following command.

```sh
python -m pip install --upgrade 'martian-sdk[evals,mcp]>=0.4.0'
```

If you created the environment with uv, use its installer.

```sh
uv pip install --upgrade 'martian-sdk[evals,mcp]>=0.4.0'
```
</Aside>

Use `martian mcp` to let a local MCP client read saved Evals and Red Team results or check supplied data over stdio. It needs no Martian account or model key. Run it only in a client you trust with your local results. If you have no saved runs yet, start with [preview mode](#3-check-a-suite-or-a-sample-before-a-run).

## 1. Connect your client

For a stdio connection, the MCP client starts `martian` and communicates with it through standard input and output. In your activated SDK environment, print the executable's path.

```sh
command -v martian
```

For a client with an `mcpServers` configuration, replace the example `command` value with that path. Replace `/path/to/evals-data` with the data-folder path printed by `martian ui`. The client can read the saved records after the workbench is closed.

```json
{
  "mcpServers": {
    "martian": {
      "command": "/path/to/venv/bin/martian",
      "args": ["mcp", "--data-dir", "/path/to/evals-data", "--project-id", "default"]
    }
  }
}
```

The server reads one project from a read-only store. Without overrides it uses the `default` project and the folder from `MARTIAN_EVALS_HOME` or `~/.martian/evals`. If the store needs initialization or an upgrade, open the folder in `martian ui` first. Configure a separate server entry for another project.

## 2. Read saved records

| To read | Call |
| --- | --- |
| Evals or Red Team run IDs, states and counts | `list_runs` (defaults to `kind: "eval"`, use `kind: "redteam"` for scans) |
| An Evals run's cases and recorded verdicts | `get_evaluation` |
| [Findings](/sdk/local-findings/) with triage state and filters | `list_findings` |
| One finding's scan and attempt references, review decisions and verified fix links | `get_finding` |
| A saved scan's [Remediation Report](/sdk/local-remediation/) | `get_remediation` |
| A baseline and follow-up's recorded results and matched coverage | `compare_remediation` |

Start with a list and use a returned ID for the detail tool. Report listings support pagination. Convert the returned `next_cursor` to an integer and pass it as `offset` to retrieve the next page.

The tools return summaries and references. Open the workbench for raw case inputs and replies, reviewer names or review comments.

## 3. Check a suite or a sample before a run

Use `"args": ["mcp", "--preview-only"]` for a client that only needs validation and deterministic checks. This starts without opening or creating a store.

- `validate_suite` reads the native suite YAML in `suite_yaml`. You can supply CSV or JSONL as `case_data.text` to check case fields. To resolve the dataset path from a suite file on disk, run `martian evals validate evals.yaml` in the terminal.
- `run_check` runs one deterministic check on the supplied sample. It takes `kind`, `options`, and `sample.output` with optional `sample.expectations`. A `passed` or `failed` verdict includes `reason`. An `error` verdict includes an `error` message.

For example, try these arguments to `run_check`.

```json
{
  "kind": "contains",
  "options": {"expectation": "branch"},
  "sample": {
    "output": "The central library opens at nine.",
    "expectations": {"branch": "central"}
  }
}
```

Expect `passed`. For a full evaluation see [Run Evals locally with a suite file](/sdk/local-evals/). To work with a Red Team target that speaks MCP, see [Review Red Team YAML](/sdk/local-redteam-yaml/).
